# Cove DuckDB 1.0.0 成本估算

本文按三个数据档位，粗略估算一个 Cove 环境每月的 AWS 费用，用于容量规划和预算参考。估算基于公开按需单价和下面列出的负载假设，不是账单，精度只到量级。实际费用以账单为准。

## 1. 前提

- **区域**：1.0.0 只支持 `us-west-2`（见[发行说明](release-notes.md#支持矩阵)）。本文用的单价取自 us-east-1，这些服务在 us-east-1 和 us-west-2 的公开单价基本相同，所以估算结果对两个区域都适用。
- **规格**：[发行规格](release-notes.md#规格)，写者与查询各为 ARM Fargate Task（2 vCPU / 4 GiB）。
- **不包含**：
  - 免费额度、Savings Plans（Fargate 与 Lambda 通常可省 20–50%）、税费与支持计划；
  - GuardDuty 等账号级服务；
  - 公网出流量（每月前 100 GB 免费，查询结果通常远小于此）。

## 2. 档位

| | 小（试用 / 部门级） | 中（单业务线生产） | 大（接近单写者上限） |
| --- | --- | --- | --- |

| 查询 Task | 1 个 | 1 个 | 2 个 |
| 流水线 | 每小时 1 次 | 每 15 分钟 1 次 | 每 5 分钟 1 次 |

## 4. 解读

- **常驻部分占大头。** 一个环境即使完全空闲，每月也约 170 USD：两个 Task 约 115，NAT 与 ALB 约 55。环境暂时不用时，执行 `admission.py close`（见[安装部署手册](installation.md#9-开放关闭与计时)），写者与查询都会停到 0，每月约省 115；NAT 与 ALB 照常计费。
- **S3 请求最不确定。** 数据库存放在 S3 上，每次提交和每次查询打开数据库都会产生对象请求，而 1.0.0 的产品成本报告不计这部分（见[性能报告](performance.md#成本范围)）。表中给出的是区间：
  - 低值假设每个写入事务约 5 次 PUT / LIST、20 次 GET，每条查询约 10 次 PUT / LIST、200 次 GET；
  - 高值按 1.0.0 性能测试当天的账号级账单反推：每个写入事务约 20 次 PUT / LIST、50 次 GET，每条查询约 20 次 PUT / LIST、300–400 次 GET。这一天的账单包含同账号其他环境的请求，所以高值偏保守。
  - 部署后，可以打开 S3 请求指标或在 Cost Explorer 中按用量类型查看，核对实际请求量。
- **数据量本身不贵。** 300 GB 的存储每月不到 20 USD。随规模增长的主要是 S3 请求、流水线计算和日志。

## 5. 容量提醒

性能实测只覆盖约 120 万条事件的表，中档与大档的容量没有验证（见[性能报告](performance.md#未运行或未验证)）。

- 大档平均每秒 1.2 次同步写，接近实测的饱和值 2.0–2.4 次提交/秒。高峰期会排队，可能返回 `429`。
- 接入（平均约 58 条/秒，实测 570–1,970 条/秒）与查询（每天 5,000 条，结果保留配额约每天 9,200 条）仍有余量。
- 计划在中档或大档规模使用时，先按[性能测试说明](performance-tests.md)在独立环境中测量。

## 6. 估算方法

单价（USD，按需公开价）：

| 项目 | 单价 |
| --- | --- |
| Fargate ARM | 0.03238 / vCPU·小时，0.00356 / GB·小时（2 vCPU / 4 GiB 约 0.079 / 小时） |
| NAT Gateway | 0.045 / 小时，0.045 / GB 处理流量 |
| 公网 IPv4 | 0.005 / 小时 |
| ALB | 0.0225 / 小时，0.008 / LCU·小时 |
| API Gateway HTTP API | 1.00 / 百万请求 |
| Lambda ARM | 0.20 / 百万请求，0.0000133334 / GB·秒 |
| DynamoDB 按需 | 0.125 / 百万读请求单位，0.625 / 百万写请求单位 |
| S3 Standard | 0.023 / GB·月；PUT / LIST 0.005 / 千次；GET 0.0004 / 千次 |
| CloudWatch Logs | 0.50 / GB 写入 |

负载换算（每月按 730 小时、30 天计）：

- **API 请求数 / 天**：每个接入批次计 2 次（提交与查询状态），每次同步写计 1 次，每条查询计 5 次（提交、轮询与读取结果），每次流水线运行计 10 次，另加 1,000 次控制台与管理请求。
- **原生写入事务数 / 天**：接入批次数 + 同步写次数 + 每次流水线运行 3 次导入。
- **Lambda**：每个 API 请求约 0.4 GB·秒；调度与回收等后台函数每月约 1 USD。
- **DynamoDB**：每个 API 请求约 30 个读单位、4 个写单位；心跳、调度等后台读写每月约 3 USD。
- **流水线**：每次运行 ECS Task（2 vCPU / 4 GiB）5–10 分钟，Lambda 0.03–0.15 GB·小时。
- **S3 存储**：原生数据 × 1.5（回收前保留的历史版本），加上 45 天接入原文（约 1 KB / 条）和约 30% 的暂存与发布版本。
- **备份**：每份约为原生数据的一半，保留 7 份。
- **NAT 流量**：每月约 20 GB 基础流量（镜像拉取、日志、队列），另按请求量少量增加。
- **日志**：每月 2 GB 基础量，每个 API 请求约 5 KB，每次流水线运行约 1 MB。

实际运行后，产品的成本报告（Admin Console 或成本接口，见[用户手册](user-guide.md#108-配额与成本)）按身份列出已计量的计算、导入、导出与构建费用。其余各项以 AWS 账单为准。
